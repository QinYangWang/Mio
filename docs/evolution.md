# 自主扩展、学习与版本演进

## 已实现的自主扩展

她能在模型运行过程中调用 create_plugin，生成一份结构化插件配方：

```json
{
  "name": "custom_top_news",
  "description": "读取当前 Hacker News 热门条目 ID",
  "url": "https://hacker-news.firebaseio.com/v0/topstories.json",
  "select": ""
}
```

运行时验证名称、HTTPS 协议、主机白名单、端口、URL 凭据与 JSON 选择器；先试读端点，再保存版本并注册 Pi tool。同名 extension 热替换，正在执行的调用沿用原实现，之后的调用使用新配方。保存后重启重载，相同配方重放不增加版本。

动态工具统一接受 query 字符串，URL 中 `{query}` 被 encodeURIComponent 替换，select 是简单 JSON 路径。禁止重定向；请求超时 15 秒，响应最多 256 KiB，模型看到最多 12,000 字符。允许域名由部署者通过 NETWORK_HOSTS 明确配置，不由聊天或模型扩大权限。

这使她可以自行新增天气、搜索、新闻、百科等 **已有 JSON API 的只读能力**。私有 API 认证、HTML 浏览、任意 npm 插件、文件写入与 shell 命令不在这套插件语言里。默认只开放官方 Hacker News 主机，不添加可解析到内网的自定义主机；当前 URL 白名单没有 DNS rebinding 防护，新增域名时必须确保它是受信任的公网服务。

## 已实现的学习

学习包含三条路径：remember_member 保存显式成员偏好/共享梗；grow 保存带真实消息依据的小步人设变化；create_plugin 保存经端点验证的新工具。前两者由模型提出候选，服务端限制来源会话、长度、变化范围和次数。

事件 ID 存在和所属会话可以确定验证，但事件是否真正支持那条记忆、偏好是否敏感、玩笑是否被当真，仍需语义评测和成员纠错。当前没有事实验证模型、关系纠错按钮或负反馈学习器。身份、管理员配置、发送权限不属于模型可修改的人设。

核心身份一旦生成不由 grow 修改。随时间变化发生在有依据的事件中，不使用随机漂移假装“长大”。没有模型权重训练、在线微调或不可解释的自主价值观重写。

## 任意代码插件与核心自更新：后续方案

用户更完整的愿景包含她自己编写 TypeScript 插件、测试、发现故障、迭代自身代码。这需要独立于群聊运行器的开发管道，本版没有把任意代码直接放入生产进程。

建议生命周期为：能力需求 → 生成 spec 与候选源码 → 隔离沙箱测试 → 静态权限分析 → 回放评测 → 签名版本 → 灰度加载 → 指标观测 → 自动回退。沙箱不持有 Slack、模型或 GitHub 生产凭据；生成代码只通过有声明的 capability RPC 调用外部能力。版本包标明 API、权限、资源上限、测试报告与迁移脚本。

真正自动激活应由预先配置的策略判定：纯只读、已批准主机、无新权限且测试通过的版本可以自动启用；新写操作或权限扩展进入管理员审查。核心代码变更走独立 Git 分支与 CI，不能让模型直接改主分支、自己的权限检查或生产凭据。发布失败保留上一个版本，并支持旧数据格式读写。

后续建议分三个增量交付：

1. **观察与反馈**：成员可纠正记忆、reaction 反馈、话题活跃度统计、群聊回放评测、模型成本预算、只读插件版本回退。
2. **隔离插件开发**：生成 TS/WASM 代码、沙箱单测、capability manifest、CPU/内存/时间配额、版本签名与灰度。
3. **受策略约束的自维护**：故障分类、日志脱敏、自动生成修复分支与测试、迁移演练、依赖升级 PR、可回滚发布。

“崩溃自愈”首先依靠确定性恢复机制；“写代码修自己”是另外一项系统能力。不要把进程重启、保存记忆或 Prompt 更新描述成已经完成任意自主编程。
