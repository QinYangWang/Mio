# 产品与行为设计

## 目标

她是一位身份透明、长期存在的 AI 群友。重要能力是判断当下回应是否合适：抱怨可以接一句，笑话可以接梗，明确求助可以认真回答，别人正聊得投入时也可以保持沉默。不要靠口头禅、故意犯错或伪造人生经历制造真人感。

初始化可以提供人设种子，也可以留空，让模型结合自身表达特点生成初始性格。人设包含稳定核心、可微调的表达维度、兴趣与版本号。成员记忆属于各自频道，不把某个成员在私密场合的资料搬到另一个频道。

## 需求落实

| 用户期望 | 本版落实 | 边界与下一阶段 |
|---|---|---|
| 被发现、加入群聊 | Slack app manifest、bot 展示、工作区安装、成员邀请 | 应用目录商业分发与多工作区 OAuth 另做 |
| 看到大家消息 | message.channels/groups/im/mpim + app_mention；过滤重复与 bot 回环 | 仅已加入且有权限的允许频道；不补取加入前历史 |
| 不依赖 @ | 所有授权普通消息入库；自主决策 silent/reply | 沉默或冷却时原始消息留作上下文，不每条调用模型 |
| 主动发起话题 | 持久化定时入队、热点工具、静默时段与每日次数 | 默认上限是主动尝试次数，沉默也消耗一次，防止不断试探 |
| 自己浏览热点 | Hacker News 来源、日期、链接，HTTPS JSON API 插件 | 本版不是任意 HTML 浏览器；可接入自建 RSS→JSON 服务 |
| 接梗、自然交流 | 上下文、稳定行为指令、共享梗记忆、短回应与沉默决策 | 语言自然度需要真实模型多轮评测，不能靠单测证明 |
| 维护成员态度 | workspace/channel/user 记忆，熟悉度、措辞与显式偏好 | 不推断敏感身份；存入资料的真实性仍需产品评测 |
| 知道上下文 | 原始频道与线程消息窗口 + Pi 会话长期记录与自动压缩 | 线程继承近期主频道上下文，不与其他线程串线；没有历史回填 |
| 并行聊天 | 不同频道/线程独立 Pi 会话，默认并发 4 | 同一主频道或线程串行，保持发言次序 |
| 有个性并成长 | 首次生成、版本化存储、兴趣变化、每天最多一次小步变更 | 核心身份不被聊天覆写；不是神经网络微调 |
| 崩溃自愈 | SQLite inbox/outbox、Pi fsync JSONL、启动恢复、外部 supervisor | 不自动诊断硬盘坏损或自行修复宿主代码 |
| 自主写插件 | 生成 JSON 配方，校验端点，动态注册 Pi tool，重启重载 | 任意 TS 代码生成/沙箱测试/自动发布属于后续工程 |
| 自学更新 | 可检验的事件依据、人设变化日志、成员记忆、新工具配方 | 模型参数、核心代码、依赖升级不由群聊自动改写 |

## 发言决策

接收到一条消息，先检查是否来自授权频道、是否 bot 消息、成员是否退出处理、频道是否暂停。再依据 @、静默时间和冷却决定是否调用模型。模型同时看到当前事件、近期原始消息、相关成员记忆和当前人设，输出沉默或回应。

@ 与私聊可绕过夜间静默和普通插话冷却，但不能绕过频道暂停或成员退出。没有 @ 的回复在生成后再次检查冷却和新消息：若生成期间频道已有新消息，丢弃这一条可能过时的插话。真正发送动作由 outbox 完成，不给模型直接访问 Slack 发消息的工具。

默认静默为台北时间 23:00–08:00，普通插话冷却 90 秒，每频道每天最多 2 次主动话题尝试，间隔至少 180 分钟。主动任务遇到未处理消息或最近刚说过话时等待。主动开场默认在频道主时间线，回应现有线程时保留 thread_ts。

## 关系与成长

每个人可以有不同的熟悉程度、适合的措辞、明确表达的偏好、共享梗。熟悉度每次有效记忆更新只增加 0.01，最大 1；最近记忆保留 12 条。行为指令要求避免永久标签化，不把“今天生气”解释成“这个人脾气差”。

人设保持姓名与核心身份，playfulness/curiosity/warmth 每次最多变化 ±0.02，范围 0.15–0.85，全球每天最多一次更新。兴趣最多 12 项，日志记录来源消息 ID、原因、频道、日期和新版本。热点可以影响兴趣，但当前 grow 工具要求群内真实消息作为依据，避免只看一条外部标题就突然变性格。

## 自然度验收

使用多轮群聊回放评测：抱怨、玩笑、反讽、梗复用、多人交叉问答、话题突变、无人回应、群成员明确要求少说话。人工评价回应是否恰当、是否抢话、是否过度解释、是否凭空引用过去、是否串错人。产品指标建议记录插话率、主动话题回复率、被要求闭嘴次数、记忆纠错率和每频道模型成本；本版暂未实现完整指标后台。
