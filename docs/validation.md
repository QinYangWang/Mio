### 2. 核心回归测试套件详情（12 项覆盖）

1. **消息去重与顺序保证**：规范化事件 ID 去重、同 Lane 严格 FIFO 顺序、失败指数退避、重启恢复运行态。
2. **上下文隔离安全性**：历史上下文窗口严禁渗入未来轮次、其他频道或非当前线程的数据。
3. **发言节奏与静默约束**：环境插话冷却时延、`/companion pause` 拦截、时区换算下的夜间静默时段拦截。
4. **异常输入与全员骚扰防御**：拒绝非 JSON 或格式不合法的模型决策；将 `<!channel>` 等全员提及自动中和为安全文本。
5. **并发隔离模型**：跨 Lane 任务并发执行（最高达并发上限），单 Lane 内部绝对串行互斥。
6. **递送不确定与崩溃自愈**：模拟发送瞬间异常导致 `uncertain` 状态，重启后通过只读元数据对账标记 `sent`，且绝不重复发送。
7. **主动话题计划与预算**：持久化每日主动开场次数预算，避让已暂停频道与近期有发言的活跃频道。
8. **用户退出隐私机制**：`/companion forget-me` 彻底擦除该用户在应用层所有频道的记忆与原始消息，并设置拦截位。
9. **插件网络安全拦截**：端点校验严格阻断内网 IP、非 HTTPS 协议、URL 用户凭据，以及原型污染字段（`__proto__`）。
10. **Pi Durable 持久化与恢复**：通过真实文件系统的 fsync JSONL 引擎持久化会话，服务重开后无损恢复长对话。
11. **人设受控成长边界**：微调幅度严格限制于 $\pm 0.02$、性格硬边界锁定在 $[0.15, 0.85]$、每日单次限制与事实依据校验。
12. **动态插件热加载与幂等**：新生成配方即时安装并生效，重启自动重载，重复配方提交不递增版本。

## 📋 上线前验收清单（Go-Live Checklist）

在将 Mio 部署至真实企业/团队 Slack 工作区前，操作员应严格逐项执行以下验收：

- [ ] **1. Slack 基础配置**
  - [ ] 通过 `config/slack-manifest.json` 正确创建应用并开启 Socket Mode；
  - [ ] 申请具备 `connections:write` 的 App Token，以及具备必要读写权限的 Bot Token；
  - [ ] 在 `.env` 中正确填入 `ADMIN_USER_IDS` 与 `CHANNEL_IDS`。
- [ ] **2. 权限与入群检验**
  - [ ] 仅当在被允许的频道执行 `/invite @小澪` 时，Bot 才进入；
  - [ ] 尝试在未加入的频道发言，确认 Bot 完全无感知并不产生异常日志；
  - [ ] Bot 自身发言不会触发消息回环。
- [ ] **3. 进程崩溃恢复演练（故障注入）**
  - [ ] 在模型生成期间直接 `kill -9` 杀掉服务进程；
  - [ ] 重启服务，确认 inbox 任务从 pending 恢复并继续完成，未丢弃事件；
  - [ ] 确认没有向频道连发两条相同回复。
- [ ] **4. 管理与隐私指令**
  - [ ] 非管理员执行 `/companion pause`，确认系统拒绝执行；
  - [ ] 管理员执行 `/companion pause`，确认当前频道插话与主动话题立即停止；
  - [ ] 成员执行 `/companion forget-me`，确认数据库内该用户成员记忆立即清空。
- [ ] **5. 安全与网络白名单演练**
  - [ ] 配置 `NETWORK_HOSTS` 为非白名单域名，诱导模型调用，确认请求在网络层被坚决拦截；
  - [ ] 诱导模型输出带有 `<!channel>` 的群呼文本，确认发出后被自动安全替换为 `"大家"`。
