# 验证记录

日期：2026-10-09。

## 已实际执行

安装并读取 Pi Durable 1.1.0、pi-ai 1.1.0、Chord 1.1.0、Slack Bolt 5.1.0 的本地类型与文档。使用 TypeScript 5.9.3 做严格类型检查。使用 Node 24.19.0 的 node:test、真实 SQLite 数据库与真实 Pi JSONL 存储执行核心测试。

全部 12 项测试通过，严格类型检查通过。测试覆盖事件去重、每 lane 顺序、失败退避、重开数据库恢复 running、上下文隔离、冷却/暂停/静默、无效模型输出、大范围提醒抑制、跨 lane 并发、发送 uncertain 核对、主动计划计数、应用层退出处理、插件 URL 边界、插件创建与版本重载、人设小步成长与每日限额，以及 Pi 会话与 requestId 跨重开持久化。

`npm run demo` 使用模拟模型决策与模拟 Slack 客户端，展示群聊消息 → 队列 → outbox → 发送流程；其语言输出是固定脚本，不用来证明真实模型自然度。

## 上线验收

在测试工作区里安装 manifest、邀请 bot、填配置；普通发言无需 @ 可以被观察，@ 可以回应，bot 的消息不形成回环。用两个频道和两个线程同时交谈，验证上下文不串线。验证暂停命令的用户权限、夜间静默与每日主动次数。首次人设生成后重启确认不重新初始化。

实际 kill 服务进程：模型调用中、工具执行中、outbox 发送前与发送后各一次。确认恢复同一 Pi requestId，pending 不漏掉，uncertain 不自动重复。演练 Slack 断线、模型 429/超时、无效 JSON、热点主机失败与数据目录权限错误。

引导模型创建允许域名的插件，确认可调用与重启重载；尝试越权主机、重定向与无效选择器，确认被阻止。触发有依据的 grow，检查版本、每日限额与变化上限。成员退出处理后检查应用数据库，并说明 Pi 转录保留限制。

完成这些验收后才能称为在目标环境验证的生产部署。本交付是核心测试通过、具备运行入口与明确边界的第一版。
